# BUG-002 - Aceita acima de 5 unidades do mesmo produto sem erros em chamadas direto na API nos endpoints POST /api/pedidos e POST /api/carrinho/calcular

**Severidade:** Alta
**Justificativa:** a API não faz cumprir o limite de 5 unidades por produto (CA10) e cria o pedido mesmo assim; a regra só existe na tela e pode ser contornada chamando a API direto. Em uma loja real, isso permitiria pedidos acima do limite, com risco de entrega fora do prazo ou pedido cancelado.
**Ambiente:** https://verzel-store.qa-test-verzel-store.workers.dev/api | Cliente HTTP: curl (terminal) | Data do teste: 06/10/2026

## Passos para reproduzir

### Reprodução 1 - POST /api/carrinho/calcular

1. Abrir um client HTTP (Postman, Insomnia ou terminal com curl)
2. Enviar a requisição abaixo:
   - **Método:** POST
   - **URL:** https://verzel-store.qa-test-verzel-store.workers.dev/api/carrinho/calcular
   - **Header:** Content-Type: application/json
   - **Body:** {"itens":[{"produtoId":"P001","quantidade":6}]}
3. Verificar no resultado o status HTTP e o body da resposta

### Reprodução 2 - POST /api/pedidos

1. Abrir um client HTTP (Postman, Insomnia ou terminal com curl)
2. Enviar a requisição abaixo:
   - **Método:** POST
   - **URL:** https://verzel-store.qa-test-verzel-store.workers.dev/api/pedidos
   - **Header:** Content-Type: application/json
   - **Body:** {"cliente":{"nome":"Maria Silva","email":"maria@exemplo.com","cep":"01310-100"},"itens":[{"produtoId":"P001","quantidade":6}]}
3. Verificar no resultado o status HTTP e o body da resposta

Atalho com curl (reprodução 1):

    curl -s -w "\nHTTP %{http_code}\n" -X POST https://verzel-store.qa-test-verzel-store.workers.dev/api/carrinho/calcular -H "Content-Type: application/json" -d '{"itens":[{"produtoId":"P001","quantidade":6}]}'

## Resultado esperado

CA10: Cada produto pode ter no máximo 5 unidades por pedido. A regra vale para a interface e para a API.

A requisição deve retornar Status HTTP 422 com o código QUANTIDADE_MAXIMA_EXCEDIDA.

## Resultado obtido

**POST /api/carrinho/calcular** (6 unidades de P001)

A API retornou HTTP 200 e calculou o carrinho normalmente, sem retornar erro:

- Produto: Camiseta Essencial (P001)
- Quantidade: 6
- Preço unitário: 59.9
- Total do item: 359.4
- Subtotal: 359.4
- Desconto: 0
- Frete: 0 (freteGratis: true)
- ValorFaltanteFreteGratis: 0
- Total do pedido: 359.4

**POST /api/pedidos** (6 unidades de P001)

A API retornou HTTP 201 e criou o pedido VZ-714610 com 6 unidades do mesmo produto (subtotal 359.4, frete 0, total 359.4), sem retornar erro.

## Observações

- Pela tela o limite é respeitado: ao chegar em 5 unidades, o botão "+" do carrinho é desabilitado e aparece "Limite de 5 unidades por produto.". O problema está só em chamadas diretas à API.
- Causa suspeita: a validação do CA10 existe apenas no front-end e não no backend.
- Em `POST /api/carrinho/calcular`, a API aceitou 5 unidades (limite exato, correto) e também 6, 100 e 1000 unidades do mesmo produto, todas com HTTP 200 e sem erro, indicando que não há limite superior validado no backend.
